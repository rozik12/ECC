# Запись сделок роботом или скриптом

Ключ создаётся в «Настройках» (карточка «API-ключ для роботов и скриптов»). Ключ показывается один раз, в базе лежит только его хэш. Удалить ключ можно там же, после этого он сразу перестаёт работать. Ключей не больше пяти.

```bash
curl -X POST https://tartib.uk/api/v1/trades \
  -H "Authorization: Bearer tt_ВАШ_КЛЮЧ" \
  -H "Content-Type: application/json" \
  -d '{"instrument":"BTC/USDT","direction":"long","entry_price":65000,"exit_price":66000,"position_size":0.1,"fees":1.3}'
```

Ответ `201` и `{"id": "..."}`. Ошибки: `401` (ключ неверный), `400` (поля неверны), `422` (нет счёта), `429` (больше 300 сделок в минуту), `413` (слишком большое тело).

Поля: `instrument`, `direction` (`long`/`short`), `entry_price`, `position_size` обязательны. По желанию: `exit_price`, `market` (`crypto`, `forex`, `stocks`, `futures`, `options`), `fees`, `funding`, `leverage`, `pnl`, `traded_at`, `closed_at` (ISO), `strategy` (до 40 знаков), `comment` (до 2000), `account` (название счёта, иначе первый счёт).

Результат (`pnl`), если не передан, считается так: `(выход − вход) × размер − комиссия − фандинг` для лонга и наоборот для шорта.

Торговые правила для таких сделок не проверяются, сделки помечаются тегом `api`. Реализация: функция `api_log_trade` в базе (миграция 20260125) и маршрут `app/api/v1/trades/route.ts`.

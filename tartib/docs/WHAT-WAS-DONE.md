# Tartib — что сделано

Tartib — веб-приложение для трейдера: калькулятор риска, журнал сделок, личные правила, статистика и «Цена дисциплины»
(сколько заработано по правилам и сколько потеряно из-за нарушений). Это не бот, не сигналы и не советы по инвестициям.

## Где что лежит

| Папка / файл | Что это |
|---|---|
| `app/` | Страницы сайта и серверные действия (`app/actions/`) |
| `components/` | Элементы интерфейса: кнопки, формы, графики, таблицы |
| `lib/` | Формулы калькулятора, проверка правил, статистика, проверка данных, переводы |
| `lib/i18n/dictionaries/` | Тексты на русском, узбекском и английском (`ru.json`, `uz.json`, `en.json`) |
| `services/ai/` | Сборка недельного отчёта (по правилам и через OpenAI при наличии ключа) |
| `supabase/migrations/` | SQL базы данных: таблицы, защита, лимиты тарифов, функции |
| `supabase/seed.sql` | Демо-данные: пользователь `demo@tartib.app`, пароль `demo12345` |
| `tests/` | Автотесты формул, статистики, CSV, AI-отчёта |
| `.env.example` | Образец настроек (ключи Supabase и др.) |

## Как запустить на своём компьютере

1. Установить Node.js (версия LTS) с nodejs.org.
2. В папке проекта: `npm install`
3. Скопировать `.env.example` в `.env.local` и вписать адрес и публичный ключ Supabase.
4. `npm run dev` и открыть http://localhost:3000
5. Проверки: `npm test`, `npm run lint`, `npm run build`

## Этапы

1. **Основа:** Next.js, Tailwind, три языка, светлая и тёмная тема, набор элементов интерфейса, лендинг, тарифы.
2. **Вход и база:** Supabase, регистрация, вход, выход, защита страниц, онбординг (имя, язык, валюта, счёт).
3. **Ядро:** правила, калькулятор с проверкой правил и оценкой X/10, журнал сделок с фильтрами, детали, правка, удаление.
4. **Аналитика:** Dashboard, статистика, графики, «Цена дисциплины», анализ эмоций.
5. **Полировка:** телефонная версия, пустые и ошибочные состояния, Настройки, Профиль, Terms и Privacy, SEO, демо-данные.
6. **AI-архитектура:** недельный отчёт, таблица `weekly_reports`, системный промпт без сигналов и прогнозов.
7. **Доработки по 15 предложениям** (см. ниже). Этап «выкладка на Vercel» ещё не делался.

## Что умеет сайт сейчас

- Регистрация, вход, выход, восстановление пароля, удаление аккаунта (нужна функция в базе, см. «Что осталось»).
- Правила 7 типов: максимум риска, минимум R:R, максимум плеча, обязательный стоп-лосс, максимум сделок в день,
  дневной лимит убытка, своё правило. Готовые примеры добавляются одним нажатием.
- Калькулятор: размер позиции, убыток, прибыль, R:R, экспозиция, маржа, лоты для Forex, целые акции; оценка X/10 только по твоим правилам;
  предупреждение «Эта сделка нарушает твои правила» (решение остаётся за пользователем); предупреждение, если маржа больше баланса;
  чек-лист перед сделкой.
- Журнал: фильтры, пагинация, стратегия, эмоция, нарушенные правила (по цифрам отмечаются автоматически), скриншот графика.
- Статистика: P&L, win rate, profit factor, средние прибыль и убыток, просадка, средний R; графики; календарь; анализ эмоций;
  «Цена дисциплины»; серия дисциплины.
- Экспорт и импорт сделок в CSV.
- Недельный отчёт (PRO). Панель владельца `/admin`.
- Установка на экран телефона (PWA).

## Тарифы

- **FREE:** до 30 сделок и до 5 правил (лимиты защищены в самой базе), статистика за 7 и 30 дней.
- **PRO:** без лимитов, статистика за всё время и по стратегиям, недельные отчёты. Оплата не подключена: PRO выдаёт владелец на `/admin`.

## Безопасность

- Защита на уровне строк (RLS) на всех таблицах: каждый видит только свои данные.
- Все данные проверяются на сервере (Zod). Пароли хранит только Supabase Auth.
- Секретный ключ service role нигде не используется. Пользователь не может сам выдать себе права владельца.
- Скриншоты в приватном хранилище, у каждого пользователя своя папка.

## Что осталось на стороне владельца

- Выполнить в Supabase SQL-функцию `delete_my_account` (текст в конце `supabase/migrations/20260104000000_plan_limits_and_account_deletion.sql`).
- Назначить себя владельцем после регистрации:
  `update public.profiles set is_admin = true where id = (select id from auth.users where email = 'ВАША_ПОЧТА');`
- Надёжные письма (своя почтовая служба в Supabase), вход через Google, ключ OpenAI, платёжный провайдер.
- Юридическая проверка текстов Terms и Privacy; контакт для связи.
- Этап выкладки на Vercel.

- Одна валюта в общей статистике (берётся валюта первого счёта).
- Статистика считается в приложении, для десятков тысяч сделок понадобится вычисление в базе.

## Дополнение: ответ на отзыв трейдеров («слабый сайт»)

1. **Импорт отчётов MetaTrader 4 и 5** (`lib/import-presets.ts`, экран `/trades/import`): HTML-отчёты (в том числе UTF-16 у MT5) и CSV распознаются сами. Берутся закрытые buy/sell, итог = прибыль + комиссия + налоги + своп, лоты переводятся в единицы (валютные пары ×100 000, золото ×100, серебро ×5 000), суффиксы брокера (`.m`, `pro`, `#`) убираются. Повторный импорт того же файла не создаёт дубликатов (то же время, инструмент и цена входа). Формат MT основан на описании платформ и проверен на образцах, а не на реальных отчётах брокеров: нужен реальный файл для окончательной проверки. Автоматическая подтяжка сделок с бирж по API-ключам НЕ сделана: Binance закрывает доступ по IP из многих регионов, хранение чужих ключей рискованно, проверить без настоящего счёта нельзя.
2. **График цены в сделке** (`components/trades/TradeChart.tsx`, `app/api/market/candles`, `lib/market-data.ts`): свечи без ключей для криптопар: источники по очереди OKX, Kraken, Coinbase, Binance (с серверов Cloudflare Binance закрыт, OKX иногда отвечает «слишком много запросов», поэтому один повтор и запасные источники; при сбое в ответе API есть поле attempts с кодами ответов), постраничная загрузка, линии входа, стопа, цели, выхода, отметка времени сделки, 5 масштабов. Цены далеко от рынка не растягивают график, а помечаются подсказкой. Для форекса, акций, фьючерсов бесплатных данных без ключа нет, показывается объяснение. Данные только вошедшим пользователям, параметры проверяются.
3. **Расширенная аналитика** (`/statistics/advanced`, `lib/analytics.ts`): ожидание на сделку, отношение прибыли к убытку, R-распределение, лонг и шорт, торговые сессии, тепловая карта «день × время», просадка от максимума, результат по месяцам, цена каждого правила, постоянство риска, серии, таблица инструментов.
4. **Приложение на телефон (PWA)**: полный манифест (ярлыки «Новая сделка», «Калькулятор», «Статистика», «Уведомления»), service worker `public/sw.js` (оффлайн-страница `public/offline.html`, кэш только неизменяемых файлов, личные страницы и API не кэшируются), карточка установки в профиле (кнопка в Chrome/Android, подсказка для iPhone). В Google Play и App Store не опубликовано: нужны платные аккаунты разработчика владельца (Google Play 25 долларов один раз, Apple 99 долларов в год) и оболочка вокруг сайта.

## Сообщения владельцу (поддержка)
- Страница `/support` (в меню «Написать владельцу», только после входа): личная переписка пользователя с владельцем, до 2000 символов в сообщении, не больше 20 сообщений в сутки (проверка в базе), обновляется сама раз в 20 секунд.
- Владелец: `/admin/messages` (список переписок, непрочитанные выделены) и `/admin/messages/<id>` (ответ конкретному пользователю). На `/admin` есть ссылка со счётчиком непрочитанных. Новое сообщение пользователя приходит владельцу уведомлением в колокольчик.
- Ответ владельца создаёт пользователю уведомление «Ответ владельца» (вид `support_reply`), в Telegram оно не дублируется.
- База: миграции `20260128000000_support_messages.sql` и `20260128000001_support_messages_fix.sql`, таблица `support_messages` с RLS: пользователь видит только свою переписку и не может написать «от имени владельца» (проверено: 403). Ответы и список идут через функции `admin_support_*`, доступные только владельцу.

## Полная проверка сайта (check-up)
- **База (миграция `20260129000000_checkup_hardening.sql`)**: 40 политик доступа переписаны на `(select auth.uid())` (результат считается один раз на запрос, а не на каждую строку, это важно при росте числа записей); у 9 функций-триггеров отозвано право вызова снаружи; двум функциям задан фиксированный путь поиска; добавлены 2 индекса под внешние ключи. Советники Supabase по производительности и безопасности после этого показывают только информационные пункты. Остаётся «защита от утёкших паролей»: включается только на платном тарифе Supabase.
- **Кэш публичных страниц** (`cf-worker.js`, `lib/page-cache.ts`): главная, калькуляторы, блог, тарифы, новости, условия для посетителей без входа берутся из кэша Cloudflare (5 минут, отдельно по языку и по версии сайта), а не собираются заново. Страницы вошедших пользователей не кэшируются. Это снижает расход процессорного времени бесплатного тарифа.
- **Легче страницы**: в браузер больше не отправляются тексты разделов, которые нужны только серверу (`lib/i18n/client-dictionary.ts`, тест следит, чтобы клиентские файлы к ним не обращались).

## 50 новых инструментов (`/tools`)
- `lib/tools-extra.ts`: 50 калькуляторов в 8 разделах: риск и размер позиции (10), форекс и CFD (8), акции и инвестиции (8), опционы и фьючерсы (5), крипто (6), золото и металлы (4), финансы (6), статистика (3). Все считаются в браузере, без регистрации.
- Тексты на RU/UZ/EN лежат в разделе `toolsx` словарей и в браузер целиком не отправляются: подписи нужного калькулятора передаёт сервер. Правки текстов вносить прямо в `lib/i18n/dictionaries/*.json` (раздел `toolsx`).
- Страница `/tools` разбита на разделы, у каждого калькулятора есть блок «Смотрите также». Все адреса попадают в `sitemap.xml`.
- Тесты `tests/tools-extra.test.ts`: формулы проверены на известных значениях, наличие подписей во всех трёх языках, отказ при неверных данных.

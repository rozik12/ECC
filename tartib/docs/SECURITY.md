# Безопасность Tartib: что есть и что остаётся на владельце

Абсолютной защиты не бывает. Ниже честный список: что проверено и закрыто, а что зависит от решений владельца.

## Что закрыто (проверено)
- **Доступ к данным.** Во всех таблицах включена защита строк (RLS): пользователь видит и меняет только свои записи. Анонимный доступ к таблицам закрыт. Проверка вживую: чужие сделки не видны, подмена `user_id` и признака «от владельца» отклоняется (403).
- **Файлы.** Бакет скриншотов закрыт, у каждого своя папка, лимит 5 МБ, только png/jpeg/webp.
- **Служебные функции базы** (проверки, триггеры) нельзя вызвать снаружи; функции владельца работают только для владельца и при включённой 2FA требуют подтверждённый вход (`aal_ok`).
- **Ключи.** В репозитории и истории git секретов нет (проверка по шаблонам ключей Cloudflare, Supabase, Telegram, Resend, GitHub, AWS). Публичный ключ Supabase (`sb_publishable_…`) предназначен для браузера и безопасен благодаря RLS.
- **Заголовки.** CSP, HSTS (с preload), X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy, COOP, CORP.
- **Зависимости.** `npm audit`: 0 уязвимостей.
- **Вход в API.** Ключи роботов хранятся только в виде хеша, 32 случайных байта; запись только своих сделок.
- **Telegram-бот.** Вебхук и служебные вызовы проверяют секретный заголовок.
- **Редиректы.** После входа разрешены только внутренние пути.
- **Вывод.** Нет `innerHTML`/`eval`; единственные два `dangerouslySetInnerHTML` содержат константу и экранированные данные.

## Что нужно сделать владельцу (самое важное первым)
1. **Включить двухфакторную защиту (2FA) своему аккаунту** (Профиль → Двухфакторная защита). Сейчас аккаунт владельца защищён только паролем, это главный риск: украденный пароль открывает панель владельца. На странице `/admin` теперь висит предупреждение, пока 2FA не включена.
2. **Supabase → Authentication → Password security**: включить защиту от утёкших паролей (нужен тариф Pro) и поднять минимальную длину пароля до 10.
3. **Supabase → Authentication → URL configuration**: в списке разрешённых адресов должен быть только `https://tartib.uk/*`.
4. **Ключи.** Когда работа закончена: отозвать токен Cloudflare, токен бота (BotFather `/revoke`), токены Supabase и Resend, которые присылались в чат, и создать новые.
5. По возможности перейти на платный план Cloudflare Workers (устойчивость к нагрузке и к простым атакам перегрузкой).

## Известные ограничения
- CSP разрешает `unsafe-inline` для скриптов (требуется Next.js без одноразовых ключей). Риск снижён отсутствием вставки чужого HTML.
- Защита от перебора паролей и регистраций держится на лимитах Supabase Auth. Капчу (Cloudflare Turnstile) стоит добавить, когда владелец создаст ключи.
- Атаки перегрузкой (DDoS) частично гасит Cloudflare, но тарифные лимиты Workers остаются.
